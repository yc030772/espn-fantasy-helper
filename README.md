# Fantasy Basketball 助手(ESPN H2H 9-Cat)

純靜態網頁,沒有後端。ESPN 的 API 開放 CORS,聯盟資料由瀏覽器直接抓。

- **選秀**:12 隊蛇型選秀板。設定你的順位後,每一手按「選走」會自動歸到當下該輪到的隊伍。
  表格同時列出 **ESPN 排序**與**我的排序**兩欄,加上兩者的**落差**,方便在兩套價值觀之間切換。
  9 個類別的加權貢獻全部攤在表上;**任一欄位標題可點擊排序,再點一次換升/降冪**。
  能補你弱項的人會反白標「建議」。附即時的**類別相對排名**與**各隊 × 各類別對照表**。
- **交易**:選好送出/得到的球員,直接看「對上這隊 9 類贏幾類」的前後變化,附 1 換 1 自動推薦。
- **總分表**:451 名球員的加權總分,每一類別的貢獻分開列,可排序、可下載 CSV。
- **FA**:排除所有已被選走的球員,依你隊上最弱的類別加權排序,並列出可以 drop 的人。

## 為什麼權重不是全部 1.0

各項數據尺度不同(PTS 25 分 vs BLK 1.2 顆),所以先做 **z-score 標準化** — 換算成「離聯盟平均幾個標準差」,這樣才能相加。

標準化之後仍然不該全給 1.0。H2H 每個類別各值一場勝負,一單位 z 的價值 = 它能把勝負翻過來的機率,
數學上 `權重 ∝ 1/σ(整隊該類別總分)`。用 10000 支隨機 13 人隊伍模擬出的 σ:

| | PTS | STL | REB | TO | AST | 3PM | FG% | BLK | FT% |
|---|---|---|---|---|---|---|---|---|---|
| σ | 3.12 | 3.25 | 3.44 | 3.51 | 3.87 | 3.93 | 4.18 | 4.21 | 4.95 |
| 1/σ 正規化 | 1.23 | 1.18 | 1.11 | 1.09 | 0.99 | 0.97 | 0.92 | 0.91 | 0.77 |

再把 TO 壓到 **0.6**:實測 TO 與 PTS 相關 −0.85、與 AST −0.86,它幾乎是純粹的用球權稅,
給滿權重等於每抽一個好球員就自己扣自己分。

最終預設:`PTS 1.25 / REB 1.10 / AST 1.00 / STL 1.20 / BLK 0.90 / 3PM 0.95 / TO 0.60 / FG% 0.90 / FT% 0.75`

權重在「總分表」分頁可直接改,或選 punt 預設組。設 0 = 棄該類別,交易頁的勝負計算會自動排除。

## ESPN 給了 2026-27 的什麼

實測 `seasons/2027` 端點(3178 人):

| 項目 | 有沒有 |
|---|---|
| 逐項數據預測(PTS/REB/AST…) | ❌ 0 筆 |
| 選秀排名 STANDARD / ROTO | ✅ 388 人 |
| ADP 平均選秀順位 | ✅ 502 人 |
| 拍賣價 auction value | ✅ 137 人 |
| 現役球隊 proTeamId(換隊後) | ✅ 全部 |

所以本站 = **2025-26 實際數據**(算戰力)+ **2026-27 排名/ADP/拍賣價/球隊**(算行情與撿便宜)。
等 ESPN 放出預測(`102027`)後,重跑 `rank.py` 就會自動接上。

## 該用去年數據還是 ESPN 預測?(實測回測)

拿 ESPN 公布的 2025-26 賽前預測、2024-25 實際數據,分別去預測 2025-26 的真實 9-cat 表現:

| 方法 | Spearman ρ | 平均排名誤差 | 前 30 命中 |
|---|---|---|---|
| **ESPN 選秀排名** | **0.906** | **25.4** | 21/30 |
| ESPN 逐項預測 | 0.809 | 46.3 | 20/30 |
| 前一年實際數據 | 0.769 | 45.7 | 18/30 |
| 混合 70% ESPN 排名 | 0.883 | 32.4 | 21/30 |

**ESPN 的選秀排名比去年數據準,混合沒有幫助。** 排序可切換,預設用自己的分數。

原因說得具體一點:受傷球員的**場均數據本身就是失真的**,不只是場次少。
Sabonis 去年 19 場只有 15.8 分 / 29.7 分鐘(健康時約 20 分 / 35 分鐘),
所以任何以去年數據為基礎的分數都會低估他 —— 收不收縮都一樣。
表上的**「落差」欄**(ESPN 排名 − 我的排名)就是用來抓這種人的:
大幅負值 = ESPN 明顯更看好,多半是去年受傷;大幅正值 = 我們更看好,可能撿便宜。

但去年數據不能丟 — ESPN 只給一個名次,不告訴你這個人強在哪一類。
類別強弱、建議標示、交易的「贏幾類」、FA 補洞,全部要靠去年的逐項數據。
**兩者分工:ESPN 排名決定「先拿誰」,去年數據決定「他補我哪個洞」。**

⚠️ 注意:無法確認 ESPN 的 2026 排名是否在球季中被修訂過。若有,0.906 會偏樂觀。
但即使只看確定是賽前的「逐項預測」(0.809),仍然贏過前一年實際數據(0.769)。

## 為什麼類別數據不用 ESPN 排名去校準

想法是:形狀取自去年數據(他強在哪些類別),量級用 ESPN 排名校準(他健康時值多少),
這樣就能救回 Sabonis 這種去年帶傷、場均失真的球星。回測 325 人,目標是 2025-26 各類別實際 z:

| 方法 | 平均相關 | 平均誤差 |
|---|---|---|
| **去年 z(現行)** | **0.824** | **0.442** |
| ESPN 校準量級 | 0.802 | 0.463 |
| 兩者各半 | 0.824 | 0.440 |

只看去年出賽 <40 場的 53 人(這招的目標族群):去年 z 0.755、ESPN 校準 0.748。**連受傷組都沒改善。**

原因:用一個純量縮放整個類別向量,不會憑空生出類別資訊,只會把本來就準的類別弄糊。**沒有採用。**

結論分兩層,並不衝突:
- **整體排序** → ESPN 排名較準(ρ=.906 vs .769)
- **各類別數值** → 去年實際數據較準(ρ̄=.824),因為 ESPN 只給一個名次,沒有類別資訊

所以 App 的排序可切換,但類別運算(建議、交易勝負、類別排名)一律用去年實際數據。

## 數據來源:等 ESPN 投影

最想要的其實是 **ESPN 的賽前逐項投影** —— 它已經把傷癒歸隊、換隊、角色變化算進去了。
但截至 2026-08-29,ESPN 只發布到 `102026`(2025-26 的投影,已經打完),`102027` 完全不存在
(全 3178 名球員、4 種 view、單一球員端點都確認過)。

程式已經接好,等 ESPN 一發布,跑同一行指令就會自動切換:

```bash
python3 rank.py --json data.json          # auto:有投影就用投影
python3 rank.py --json data.json --source proj    # 強制用投影(沒有會明確報錯)
python3 rank.py --json data.json --source actual  # 強制用上一季實際數據
```

## 名單涵蓋範圍

主檔用**新球季**名單(2027),再左連接上一季數據 —— 不是反過來。
早期版本拿舊球季當主檔又用 `GP>=20` 過濾,結果 Sabonis(ESPN #9)、Trae Young(#11)、
Tatum(#12)這些去年打不到 20 場的人整批從選秀板上消失,新秀更是完全沒出現。

目前 639 人:樣本充足 401、小樣本(<20 場)59、無數據 179(含 161 名只有 ADP 的新秀)。
無數據球員的類別貢獻算 0(未知,不是負分),在隊伍統計裡以 `+N?` 標示未計入。
